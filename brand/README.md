# Brand

The mark is not artwork. It is the same geometry the app teaches, and it is
generated from three angles by `make-brand.cjs`. Nothing in this folder should
ever be opened in an illustrator and nudged.

```
npm run brand      # regenerates every SVG, then the iOS raster
```

The three SVGs that came with the original set — `aspect-mark.svg`,
`aspect-lockup.svg`, `aspect-favicon-tiny.svg` — regenerate **byte for byte**.
That is the check that the generator is still the source of truth rather than a
script that once produced something like the artwork.

---

## The rule that must never be broken

**The three sectors are 112.5°, 112.5° and 135°, and they total exactly 360°.**

| Sector | Angle | Colour | What it is |
|---|---|---|---|
| Starboard | 112.5° | `#00A862` green | The starboard sidelight arc |
| Port | 112.5° | `#CE2019` red | The port sidelight arc |
| Stern | 135° | `#FFFFFF` white | The sternlight arc |

Those are Rule 21's arcs, not a designer's choice. `112.5 + 112.5 + 135 = 360`
is why the mark closes into a ring with nothing left over, and it is the whole
idea of the thing: the logo is a vessel's light pattern seen from directly
above.

**Redraw it at other angles and the logo starts contradicting Rule 21 on every
page it appears on.** A study aid whose own badge is wrong about the rules it
teaches has a credibility problem it cannot argue its way out of.

`test/brand.test.js` reads the angles back out of the drawn path and fails if
they move. It does not take the generator's word for it.

## Palette

| | Hex | Used for |
|---|---|---|
| Starboard green | `#00A862` | The starboard sector |
| Port red | `#CE2019` | The port sector |
| Sternlight white | `#FFFFFF` | The stern sector |
| Ink | `#0E1F28` | Edges, compass rose, ticks, wordmark, theme colour |
| Paper | `#E7EEF0` | Backgrounds, and the edge colour in the night mark |

Night variants brighten the lights so they hold up on a dark ground —
`#00B86E` and `#E02B22` — and swap the ink for paper. Same geometry, different
palette; `aspect-mark-night.svg` is the reference.

`aspect-mark-mono.svg` and `aspect-mark-reversed.svg` exist for the cases where
colour is not available at all: one ink, or one paper. They drop the white
sector to an outline rather than filling it, because a white fill on a one
colour mark is a hole.

## The three favicon levels

The compass detail dies as the icon shrinks. Rather than let a browser do the
reducing, there are three drawings at three levels of detail, and each is used
where it survives.

| File | Level | What is in it | Where it is used |
|---|---|---|---|
| `aspect-favicon-tiny.svg` | 16px | **Arcs only.** No compass rose, no ticks, heavier stroke, arcs pushed out to r20–46 to fill the box | Browser tab. At 16px the compass arrows are three or four pixels and collapse into specks that read as dirt on the icon |
| `aspect-favicon.svg` | 32px | **Arcs plus the arrows.** The four cardinal and four intercardinal spikes, still no tick ring | Bookmarks bar, tab at 2× |
| `aspect-mark.svg` | full | **Everything.** Arcs, arrows, the ring and its twelve ticks | Header lockup, social card, anywhere it is drawn above about 48px |

Two rasters carry the same mark where a vector is not accepted:

| File | Size | Where |
|---|---|---|
| `apple-touch-icon-180.png` | 180×180 | iOS home screen |
| `aspect-mark-512.png` | 512×512 | The web app manifest |

`apple-touch-icon-180.png` is **derived, not drawn**: `make-icons.cjs`
area-resamples it from the 512. There is no rasteriser on the build machine, and
redrawing it would mean two sources of truth for a mark whose whole point is
that it is one.

## The lockup

`aspect-lockup.svg` is the reference for proportion and letter-spacing. The
header in `index.html` rebuilds it in HTML rather than embedding the SVG, so the
mark can take the night palette from CSS custom properties, and it keeps the
lockup's ratios:

| | In the lockup | Why it carries across |
|---|---|---|
| ASPECT tracking | `4.9 / 38em` = `.1289em` | Letter-spacing set in em is scale-free |
| Strapline tracking | `3.2 / 12.5em` = `.256em` | Same |
| Rule height | `48 / 72` of the mark | |
| Gap, mark to rule | `20 / 72` of the mark | 10px at a 36px mark |
| Gap, rule to text | `22 / 72` of the mark | 11px at a 36px mark |

**One deliberate deviation.** At a 36px mark the lockup's ratio puts the
strapline at 6.25px. Below about 8px the tracking closes up and RULES OF THE
ROAD reads as a smear rather than as words, so it is set at 9px. Everything else
is the ratio.

## What is generated and what is not

Generated by `make-brand.cjs`, safe to delete and rebuild:

```
aspect-mark.svg            aspect-favicon.svg         aspect-lockup.svg
aspect-mark-night.svg      aspect-favicon-mono.svg    aspect-lockup-night.svg
aspect-mark-mono.svg       aspect-favicon-tiny.svg    aspect-social.svg
aspect-mark-reversed.svg
```

Derived by `make-icons.cjs`, also safe to delete and rebuild:

```
apple-touch-icon-180.png
```

**Not generated** — these came with the original set and cannot be rebuilt here,
because rasterising an SVG needs a renderer this machine does not have:

```
aspect-mark-512.png        aspect-social.png          aspect-lockup.png
```

If you ever regenerate those, do it from the SVGs in this folder, at
512×512, 1200×630 and 840×200 respectively.

## The bundle

`aspect-standalone.html` runs from `file://`, where `brand/aspect-favicon.svg`
resolves against whatever folder someone dropped the file in. So `build.cjs`
inlines both favicons as data URIs and drops the manifest and the PNG icon links
entirely — a file:// page has no home screen and no manifest.

The Open Graph and canonical URLs stay in the bundle. They are absolute https,
they are metadata a crawler reads rather than anything the page loads, and
stripping them would leave the served copy without a preview card.

`test/brand.test.js` asserts the built file loads no image from anywhere.
